# Lifecycle Event Map and Trigger Plan (A21)

This document defines the A21 lifecycle automation map and trigger plan for Klaviyo and PostHog, driven by real MTM and booking state.

## Event Map

| Event | Trigger | Source of Truth | Window | KPI |
| --- | --- | --- | --- | --- |
| `saved_fit_reactivation_sent` | Profile enters pre-stale reactivation window | `FitProfile.updatedAt` + A17 freshness policy | 150-179 days since update | Reactivation click rate |
| `refit_reminder_sent` | Profile is stale and refit should be prompted | `FitProfile.updatedAt` + A17 stale threshold | >= 180 days since update | Refit booking start rate |
| `booking_pre_event_reminder_sent` | Confirmed booking approaches appointment | `Booking.startAt`, `Booking.status=confirmed` | 24h before appointment | No-show reduction |
| `booking_post_event_followup_sent` | Booking exits appointment and enters follow-up window | `Booking.startAt`, `Booking.status!=cancelled` | 48h after appointment | Repeat purchase rate |
| `booking_confirmed` | Booking created with confirmed status | Booking API create flow | Immediate | Confirmation delivery rate |
| `booking_fit_refresh_required` | Booking held pending fit refresh | Booking API create flow | Immediate | Fit refresh completion rate |
| `booking_rescheduled` | Booking date/time updated | Booking update/reschedule APIs | Immediate | Reschedule completion rate |
| `booking_cancelled` | Booking cancelled | Booking update API cancel action | Immediate | Rebook recovery rate |

## Trigger Plan

### Klaviyo

- Send metric event for each lifecycle trigger listed above.
- Metric name format: `[prefix_]event_name`.
- Prefix source: `KLAVIYO_LIFECYCLE_EVENT_PREFIX` (fallback: `KLAVIYO_BOOKING_EVENT_PREFIX`).
- Required profile identity: customer email.
- Event properties should include campaign identifiers and source path.

### PostHog

- Capture event name exactly as listed in the event map.
- Distinct ID priority:
  1. Customer ID when available
  2. Booking ID or FitProfile ID
  3. Stable synthetic fallback generated by flow
- Include these baseline properties:
  - `lifecycleEvent`
  - `source`
  - `campaignId` (when email campaign flow)
  - state identifiers (`bookingId`, `fitProfileId`, `serviceType`, `startAtIso`, `profileAgeDays`)

## Automation Hook Points

- Booking create flow: emits `booking_confirmed` or `booking_fit_refresh_required`.
- Booking reschedule flow: emits `booking_rescheduled`.
- Booking cancel flow: emits `booking_cancelled`.
- Lifecycle cron (`/api/automation/lifecycle-reminder-cron`):
  - saved-fit reactivation reminders
  - stale-profile refit reminders
  - pre-event booking reminders
  - post-event follow-up reminders

## Idempotency Strategy

- Fit profile reminder flows persist markers in `FitProfile.technicalSpecs.notifications.lifecycle`:
  - `saved_fit_reactivation_sent_at`
  - `refit_reminder_sent_at`
- Booking timeline flows append lifecycle markers to `Booking.notes`:
  - `[lifecycle:pre_event_reminder_sent]`
  - `[lifecycle:post_event_followup_sent]`

## Operational Notes

- Vercel cron schedule: every 3 hours (`0 */3 * * *`) to support timeline windows.
- Endpoint supports `?dryRun=1` for safe verification.
- Secret header protection: `x-vercel-cron-secret` must match `VERCEL_CRON_SECRET` when configured.
